## Stage 1 — move already owned publication bytes

`selected_bytes` used the bounded file-reading helper on an owned byte vector,
allocating and copying the whole payload again. It now reuses the same size
validator and moves the buffer, retaining configured/hard limits and error text,
stored-length checks, stale revision checks and captured MIME authority.
The existing local-image action test also checks rejection below payload size.

Validation/results are recorded with each stage below.

Stage 1: `cargo test --locked --all-features --lib history::mutation::tests`
(2 passed) and `... --lib selection::tests` (1 passed); rustfmt and diff checks
pass. Post-initial `rqlens measure hotspots` succeeds (`stage-1-hotspots.json`).

## Ranked next five, selected after stage 1

1. Read/validate annotation output once and commit those exact bytes: the old
   path read once for full PNG validation and reopened for commit, allowing the
   second read to differ. Preserve PNG/size/dimension/regular-file guards.
2. Reuse resolved content inside storage insert/replace: both resolved twice,
   including file URI parsing, metadata and image header I/O. `write_content`
   remains a hotspot (cognitive 13, cyclomatic 24, Halstead effort 76,430.72).
   Identity/ownership must still be checked at the echo decision.
3. Share sidecar validation: startup repeats the commit/shutdown owner checks;
   `Database::open` is the largest production hotspot (cognitive 21, cyclomatic
   53, effort 155,123.84). Keep nofollow/type/link/owner checks and reject dangling
   sidecar symlinks as consistently as ordinary symlinks.
4. Preflight file-publication size before constructing a second full URI payload:
   currently allocates/copies even for rejected input. Reuse the size validator
   and preserve exact copy/cut wire bytes and error semantics.
5. Isolate owner-admission process evidence from socket-slot saturation: the
   baseline and isolated repeat fail at line 980, immediately after audit-based
   cancellation observation. Cancellation is not a connection-slot-release
   acknowledgement. Preserve the 64-operation global limit and all peer/receipt
   assertions; socket connection bounds belong to shared transport tests.

The larger privacy/Wayland state machines were left intact: extracting wrappers
would shift metrics without removing work. Bounded preview/trigram rewrites are
lower priority than these verified copy, validation and duplicated-I/O paths.

## Stage 2 — commit the validated annotation buffer

`read_edited_image` returns the exact fully decoded PNG bytes; annotation commits
that buffer and screenshot publication uses it too. It retains regular-file,
configured/hard byte, PNG-only, dimensions
and full-decode guards. The existing five-format/size cases, symlink and truncated
PNG checks remain; successful validation now also proves the buffer survives a
subsequent file replacement. This closes the second-read gap, not all possible
filesystem races between metadata and the initial open.

Stage 2: `cargo test --locked --all-features --lib history::` passes 16 tests,
including image formats/limits, screenshot commands, operation cancellation and
partial publication. Rustfmt/diff checks pass. The first compile identified the
remaining screenshot caller; it was migrated to the same validated-buffer owner.

## Stage 3 — reuse storage content resolution

Insert and replacement pass their already resolved content to `write_content`,
removing a second URI parse/image-header read. This is shared transaction data,
not a new forwarding layer. Echo authorization still reads current metadata and
checks device/inode/owner, registered source existence and exact image identity.
Full-text content, all URI references, digest/byte equality, retention and revision
transactions are unchanged. Existing real-engine tests independently exercise
Unicode/literal search, replacement rollback, URI references and image echoes.

Stage 3: `cargo test --locked --all-features --lib history_store::` passes 7;
`cargo test --locked --test turso_storage` passes 18, including 64 MiB exact
restoration, native FTS, rollback and generated URI echo invalidation. Rustfmt
and diff checks pass. No new duplicate test owner was added.

## Stage 4 — share fail-closed sidecar validation

One owner validates sidecars before engine open and after commits/checkpoints.
It uses symlink metadata before nofollow open, preserving file/type/link/UID/mode
guards and fencing on post-commit protection failure. The previous post-commit
`try_exists` path followed links and could overlook a dangling sidecar symlink;
it now rejects that case too. The existing private-path test is parameterized
over lock/WAL/SHM and existing/dangling targets (six rejection cases), retaining
the existing single-owner, restart, permissions and database-symlink assertions.

Stage 4: storage integration 18 and fault subprocesses 8 pass; after adding the
post-commit regression, `cargo test --locked --lib history_store::` passes 8,
including a real COMMIT followed by dangling-SHM protection failure and fencing.
`cargo test --locked --test turso_storage owner_lock_private_modes_and_symlinks_fail_closed`
passes its six-case matrix on the final stage tree. Rustfmt/diff checks pass.
Logs: `stage-4-tests.log`, `stage-4-final-tests.log`.

## Stage 5 — reject oversized file offers before copying

Validate the complete URI-list plus copy/cut header length before concatenating
the GNOME representation. Both formats keep exact bytes; invalid operations still
fail before publication. The existing publication test now parameterizes both
operations at the exact boundary, checks both GNOME and URI offers, and rejects
copy/cut over the limit plus an invalid operation before any publisher calls.

Stage 5: final `cargo test --locked --all-features --lib selection::tests` passes
1 parameterized test; `cargo test --locked --all-features --test api` passes 5.
Rustfmt/diff checks pass. Final exact-boundary cases and literal GNOME headers
are in `stage-5-final-tests.log`; API results are in `stage-5-tests.log`.

## Stage 6 — isolate owner admission from socket-slot lifecycle

The private process harness reserves five socket slots for four saturated
operation owners and the replacement/observer. Production `config()` remains at
four connections. Domain cancellation audit records do not acknowledge transport
slot release; the old fixture depended on that ordering. All 64-operation global
admission, 16-operation owner limits, abandoned-owner receipts, healthy-peer
status and capacity-after-completion assertions remain. Shared framework socket
tests own transport connection limits. Busy requests reuse one fixture value and
completion control reuses the existing atomic marker writer, reducing duplicated
test setup without removing behavior checks.

Stage 6: the previously failing process test passes three consecutive actual
executions with `cargo test --locked --all-features --lib real_process_owner_cleanup_retains_committing_admission_and_healthy_peers`.
Each run executes one test, preserving all admission/receipt/peer assertions.
Rustfmt/diff checks pass. Log: `stage-6-tests.log`.
